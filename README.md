# VoiceChat Web 1.2

Браузерный голосовой чат на Node.js, WebSocket и WebRTC. Клиент работает в Chrome/Edge и на мобильных браузерах.

## Что добавлено в этой версии

- Компактная двухколоночная компоновка для ПК: боковая навигация и рабочая область.
- Настройки и профиль вынесены в отдельные пункты меню слева.
- Уменьшены отступы, карточки, заголовок лобби и блок участников; быстрые действия собраны компактно.
- На телефонах сохранена нижняя панель навигации, а содержимое адаптируется под узкий экран.

- Регистрация по email и паролю (минимум 8 символов).
- Подтверждение почты шестизначным кодом.
- Вход, выход, восстановление пароля по email.
- Пароли хранятся как scrypt-хеши с уникальной солью, а не в открытом виде.
- Сессии сохраняются на сервере и действуют 30 дней.
- Профиль привязан к аккаунту: имя, статус, аватар.
- Эмодзи-панель в сообщениях.
- Реакции на сообщения, с подсчётом участников реакции.
- История последних 80 сообщений комнаты и реакции хранятся в памяти комнаты до перезапуска сервера.
- Существующие голосовые комнаты и WebRTC mesh сохранены.

## Локальный запуск

Требуется Node.js 20 или новее.

```powershell
cd VoiceChatWeb
npm install
npm start
```

Откройте `http://localhost:8787`.

### Тестовая почта без SMTP

Если SMTP не настроен, сервер выводит код подтверждения в консоль и показывает его в форме регистрации/восстановления. Это режим разработки, чтобы можно было протестировать авторизацию без почтового провайдера. Не используйте его на публичном сервере.

### Реальная отправка писем

Создайте SMTP-учётные данные у почтового провайдера. В PowerShell задайте переменные перед `npm start`:

```powershell
$env:SMTP_HOST="smtp.example.com"
$env:SMTP_PORT="587"
$env:SMTP_SECURE="false"
$env:SMTP_USER="mailer@example.com"
$env:SMTP_PASS="ВАШ_SMTP_APP_PASSWORD"
$env:MAIL_FROM="VoiceChat <mailer@example.com>"
$env:NODE_ENV="production"
npm start
```

Поменяйте значения на параметры своего провайдера. Для SMTP используется пакет Nodemailer, который устанавливается командой `npm install`.

## Данные и безопасность

- Аккаунты и активные сессии записываются в `data/auth-store.json`. Сделайте резервную копию этого файла.
- Не публикуйте `data/auth-store.json`, SMTP-пароль или папку `data` в открытом доступе.
- Для публичного использования обязательно включите HTTPS/WSS через reverse proxy (например, Caddy или nginx), настройте SMTP, ограничение частоты запросов и резервное копирование.
- Микрофон в браузере доступен на `localhost` или по HTTPS.
- Для связи между разными сетями может понадобиться собственный TURN-сервер.
- Голосовая связь реализована mesh-соединениями WebRTC. Для больших групп нужен SFU.
- Комнаты и сообщения пока живут в памяти процесса и очищаются после перезапуска. Аккаунты и сессии при этом сохраняются.
- Каталог комнат общий только для одного запущенного экземпляра сервера.

## Проверки

```powershell
node --check .\server.js
node --check .\public\app.js
npm start
```

Проверка состояния: `http://localhost:8787/health`.


## Начальное лобби
После входа пользователь остаётся на стартовой странице и не подключается автоматически к общей голосовой комнате. Можно выбрать «Создать комнату» или «Присоединиться» (каталог/код приглашения). Выход из комнаты возвращает на начальную страницу. Общей комнаты по умолчанию больше нет.
